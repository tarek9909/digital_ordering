# Application requirements audit — 2026-10-22

This review compares the BRD, TRD and implementation plan with application code. It excludes DevOps and the explicitly deferred Phase 9 backlog. It is a source trace plus eight isolated runtime reproductions, not a claim that every requirement has passed acceptance.

Reproduction: from `backend`, run `npx tsx ../docs/audits/2026-10-22/requirements-probe.mts`. The probe starts its own throwaway MySQL database, uses real HTTP handlers and TOTP, stubs Google identity verification, and stops the database in `finally`. It never calls Google, Stripe or Foodics. The relocated script completed successfully; output is saved in `requirements-probe-results.json`.

## Unverified concern and external acceptance limits

- Purge recovery was subsequently confirmed by the consolidated audit: `final-fault-probes.mts` injected a temporary storage failure after the tenant row was removed. Retry returned done without removing the two stored objects or tenant KV data. See REPORT.md finding A30 and `final-fault-probes.jsonl`.
- Foodics signatures/status/location fields explicitly await partner-document confirmation (`backend/packages/services/src/connectors.ts:39`). Partner credentials/certification are an external acceptance blocker; the missing connect workflow in S01 is a separate application omission.
- Real Google OAuth client execution, Stripe test-mode payments/tax/portal/proration, real Web Push delivery, iPhone/Android/browser behavior and TV voice quality require the external accounts/devices listed in the implementation plan. Their absence is not itself a code defect, and stub/fake tests do not establish their live acceptance.
